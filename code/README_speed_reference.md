# 与 2026_9_short_term 的速度环对照

参考源码：`C:/Users/34494/Desktop/2026_9_short_term/MiniBalance/CONTROL/control.c`，实际入口为 `USER/MiniBalance.c`，不是 `99-上课例程`。`race_control.c` 统计赛道圈数和距离，不实现速度 PI。此次只读取参考工程，修改位于本 TC264 工程。

## 实际调用与公式

参考的 MPU DMP 频率为 200 Hz，每 5 ms 进入 EXTI；编码器在每次 EXTI 中读取并清零。`Flag_Target` 使直立和速度控制隔一次中断运行，所以两者实际均为 10 ms，姿态估计为 5 ms。

参考 `Velocity()` 的有效逻辑可写成：

```text
measurement = left_5ms_count + right_5ms_count
bias = 0.84 * bias - 0.16 * measurement
integral = clamp(integral + bias + target_counts, 380000)
speed_pwm = -bias * Velocity_Kp / 100 - integral * Velocity_Ki / 100
motor_pwm = upright_pwm + speed_pwm ± turn_pwm
```

其目标计数按目标速度、轮周长、编码器参数、200 Hz 和左右轮数量换算。P 只作用于测量；目标仅进入积分。这种目标处理与本工程的普通误差 PI 不同，改变目标时不会产生同样的 P 跳变。参考积分没有显式 dt，Ki 为每次调用的离散系数；本工程 `I += Ki * error * 0.02` 的 Ki 则按秒定义。两者还有 count/PWM 与 m/s/度的单位区别，不能只将 Kp=400、Ki=2 或除以 100 后的值搬到菜单。

参考 PI 每次更新只消费最后一个 5 ms 计数窗口，另一个窗口已经在提前返回的中断里读走。它自身也没有完整利用 10 ms 的编码器计数，不能把这个采样遗漏照搬到 TC264。

## 本工程此次修正

原来每 20 ms 直接取最新一笔 2 ms filtered 作为 PI 反馈。现在将十笔 2 ms filtered 的平均值交给 PI，完整利用该控制周期的测量，避免短时计数恰好落在最后一笔时形成过大的 P 请求。

2 ms raw/filtered 计算和显示、raw 占 90%、20 ms PI 周期、按秒积分、常规 `error = target - feedback`、倾角输出及已有方向保持当前定义。输出仍直接送给直立目标角，不增加输出斜坡。窗口平均相对最新采样有约 9 ms 的平均数据年龄，降低抽样波动需要与实车响应延迟一起验证。

参考在每 10 ms 才更新一次 16% 新值滤波，本工程每 2 ms 更新 90% 新值，反馈平滑程度差异很大。用户已指定 90% raw，本次不擅自调整该权重。

本工程未限幅时，速度倾角进入电机共模的贡献为 `BALANCE_KP * speed_angle`。例如直立 Kp=1700、速度 Kp=4，速度误差变化 0.1 m/s 会改变 0.4° 的倾角请求，对应瞬时约 680 PWM 的共模变化。直立 Kp 改动也会改变速度环对电机的作用强度。这是解释参数时需要考虑的耦合，不足以单独证明哪个实车增益稳定。

参考 STOP 清积分，但保留滤波状态；本工程 STOP 清积分和倾角请求，继续发布编码器实测速度。参考输出直接相加到 PWM，与本工程倾角输出的形式差异，在直立 Kp 固定、未限幅时可展开比较，不能仅凭这点认定一种形式错误。

## 验证与结论边界

主机测试覆盖最后一笔脉冲不会代表整个 20 ms、第一笔脉冲仍参与 PI、左右轮独立标定、2 ms 数据即时更新、20 ms 积分、RUN/FOLLOW 门控和 STOP 清积分。现有 FireWater 22 列保持不变，第 8 列现表示完整 PI 窗口平均值。

这项修正解决反馈采样遗漏，不代表先前赛道失控已解决。已有日志还包含姿态瞬变、转向作用和 43 秒计时回绕；需要刷入新固件后的完整实车记录才能确认收敛。

## 持续超速与前倾的补偿

用户确认车体向摄像头方向前进时，两轮编码器计数均为正，并报告前倾时 COMP ANGLE 减小。按这个实车方向，当前正速度误差降低目标倾角、超速提高目标倾角，目标倾角修正方向符合前倾加速、后倾减速的要求。方向符合要求不代表闭环已经稳定；不能凭瞬时 PWM 与轮速同号就把速度反馈反号。

220907 在设备时间 41900～42860 ms 的 46 帧中，目标平均 0.8 m/s、PI 反馈平均 1.286 m/s，P 倾角平均 −1.946°、I 倾角平均 −0.030°。实际角度比目标平均低 0.897°，直立共模平均仍为 +1550 PWM。这能证明存在持续速度偏差和很弱的积分补偿，不能证明只提高积分就一定稳定，也不能由“速度 PI 已启用”推导出“速度已经稳住”。

当前积分按秒定义。若持续超速 0.5 m/s，则 Ki=0.01 每秒仅累积 −0.005°，累积 −1° 约需 200 秒；Ki=0.5 则每秒累积 −0.25°。在 20 ms 周期中，Ki=0.5 相当于每次 `I += 0.01 * error` 的离散累加强度。这个换算只适用于相同的 m/s 输入和度输出，不能拿来直接换算参考工程的 count/PWM 增益。

实际控制代码的主机测试验证了：持续约 0.52 m/s 超速十秒时，Ki=0.01 的 I 修正约 −0.052°，Ki=0.5 约 −2.60°；变为零误差后仍保留已积累的倾角修正，STOP 才清除。测试没有模拟真实车体，不能代替闭环稳定性验证。

20261012_185704 实车日志使用目标 0.5 m/s、速度 Kp≈3、Ki≈0.5，仍发生加速失控，最高 2 ms 滤波速度 5.89 m/s，最终两轮 PWM 均达到 +10000。因此撤回将 Ki=0.5 作为下一步起点的建议，不能把积分弱作为所有失控的已确认主因。

20261012_190013 的机械中值为 +2.832°，与 185704 的 −3.409° 不同。用户确认这是手动修改。该次目标 0.5 m/s、Kp≈3、Ki≈0.01，车在地上无人扶着但基本不走；比例与积分合计约 1.64°，目标角约 +1.19°，实际角约 +1.15°。这不能直接用来测定真实机械平衡点，也不能与中值不同的前一份日志当作仅改变 Ki 的对照实验。

20261012_190957 使用相同中值 +2.832°，目标 0.8 m/s、Kp≈10、Ki≈0.01。速度 PI 连续运行 52.248 秒，平均反馈 0.512 m/s；去掉前 4 秒后，平均反馈 0.522 m/s、误差 0.278 m/s、P=2.781°，I 在结束时仅 0.150°，此阶段没有倾角或电机饱和。说明该次控制主要依靠持续速度误差产生比例补偿，积分消除偏差很慢：按 0.278 m/s 固定误差，每秒约积累 0.00278°，增加 1° 约需 360 秒。所需持续倾角还受机械中值、姿态反馈和行驶负载影响，日志不能唯一分离这些因素。

该次启用速度 PI 时，目标从 0 跳到 0.8 m/s，比例修正立即约 −8.09°；随后短暂达到 −10° 限幅，反馈轮速最低约 −0.731 m/s。提高 Kp 会同时加大启动时的角度跳变，不能把提高 Kp 当作解决持续速度偏差的唯一办法。保留用户要求的直接 PI，不添加启动斜坡或输出速率限制。
